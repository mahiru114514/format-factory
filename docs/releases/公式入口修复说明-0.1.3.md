# 公式入口修复 · 桌面 0.1.3

本次用户截图中，运行的确实是桌面 0.1.2，但处理方式为“图片 / PDF 文字识别”。旧版的版本号显示曾被写死为 1.0.0，因此不能据截图判断实际版本。本次同时修复入口问题和实际图片中的大逻辑符号方向误识。

## 如何使用

双击项目根目录的 **启动公式识别.cmd**，程序直接进入文本处理的“单条公式识别”。标题和左下角均显示 **0.1.3**。导入或粘贴公式截图，框选完整的一条公式，再点击 **识别公式**。另提供 `.vbs` 无命令窗口入口；受限环境中脚本宿主可能等待，遇到此情况请使用 `.cmd`。

普通图片导入仍默认使用文字识别，以支持普通文字截图。该模式下主按钮显示“识别文字”，并常驻提示：公式的箭头、上下标可能丢失。旁边增加 **识别这张图中的单条公式** 按钮，点击后直接切到公式引擎并识别。已编辑结果仍会先确认是否覆盖；拒绝后原编辑和处理方式均保留。

## 本次截图的实际结果

使用本次截图中黑底公式区域的像素（原图坐标 382,701 至 1093,911），不更改公式内容：

- 普通文字引擎：`used[t]` 与 `V(slot[i] = t)`，关系符号和上下界丢失。
- 公式引擎原始预测：关系符号与上下界保留，但误把 `\bigvee` 识别成 `\bigwedge`。
- 本版识别及方向校验后的可读结果：

```text
u s e d[t] ⟺  ⋁_{i=0}^{5}(s l o t[i]=t)
```

变量字母间距和箭头样式仍须核对。这是实际生成结果，没有硬编码变量、上下界或整条公式答案。

## 大逻辑符号校验的范围

只在模型预测单个大析取/合取、命令带上下界、图中对应位置有上下界小字且只有一个足够清楚的对称 V/∧ 形状时，检查笔画方向。出现其他大小的 V/∧、可能的变量 V/Λ、复杂或弯曲形状、缺少上下界等情况时，保留模型输出。

此检查仅用于有限的方向误识，不能保证上下界数字、变量名及所有公式都准确。仍需人工核对。不会把普通文字截图自动猜成公式；公式按钮和专用启动入口让用户明确选择处理类型。
