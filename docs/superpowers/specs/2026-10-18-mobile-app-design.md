# 格式转换工厂：iOS / Android 手机 App 设计稿

日期：2026-10-18
状态：用户于 2026-10-18 确认本设计，开始实施手机端第一版。

## 已确认的需求

- 同时支持 iPhone 和安卓。
- 本机处理优先；复杂转换只有用户同意后才能上传服务器。
- 延续桌面版的文档、表格、图片转换和文本识别/整理能力。
- 文本处理的核心价值仍是：导入或粘贴 → 转换/识别 → 核对 → 编辑 → 复制；保存 TXT 为辅助。

## 推荐的落地方式

使用 Flutter 构建两端共用的手机界面，平台差异通过原生适配处理。本地转换模块与联网转换服务分离；服务端复用现有 Python 转换逻辑，并移除对桌面界面及 Windows Word 的依赖。

备选方案：Swift / Kotlin 分别开发，两端维护工作较多；移动网页 / PWA 便于试用，但文件分享、后台任务和系统集成需要额外核对。按用户要同时支持两端的目标，推荐 Flutter。

## 首版功能和处理位置

| 功能 | 处理策略 |
|---|---|
| 文本粘贴、LaTeX 源码保留、常见 LaTeX 转可读文本 | 手机本地；未知语法不得静默丢弃 |
| 编辑、撤销、复制全部 / 选中内容、保存 TXT | 手机本地，不依赖服务器 |
| 常见图片转换、压缩、尺寸调整 | 本地优先；HEIC 读写能力按平台及设备验证，不能支持的目标不伪装可用 |
| XLSX / CSV 转换 | 手机本地；保留长编号、前导零，多工作表分别导出 |
| 普通中文 / 英文图片文字识别 | 本机识别优先；任何识别资源准备与文件上传分开说明 |
| Markdown / TXT 基本文档输出 | 尽量在手机完成，实际支持格式以本地引擎验证为准 |
| 复杂 Word / PDF 互转、扫描文档恢复、单条公式识别 | 使用联网服务；上传前确认，结果回到手机核对、编辑、保存或分享 |

首版不将“支持 iOS / Android”解释为每种照片编码在每台设备上都可生成。必须验证原生解码、方向、透明背景及 HEIC 目标编码；需要服务端兜底时明确询问用户。

## 手机交互

底部入口为“转换、文本、任务、设置”。转换首页按文档、表格、图片分组；文本入口集中提供粘贴、图片/截图、拍照和 PDF 输入。

- 从系统文件选择器或相册选取文件，支持多个文件。
- 通过系统分享接收文件，并把结果保存到文件、相册（仅兼容图片），或分享给其他 App。
- 手机纵向界面使用可折叠原文预览和结果编辑区；原文支持放大和 PDF 切页。
- 结果区支持直接编辑、撤销及系统选区操作；“复制全部”固定在容易触达的位置，复制当前编辑内容，保留 LaTeX 反斜杠、花括号和换行。
- 再次转换前保护用户修改；更换输入不直接清除编辑结果。
- 任务页展示本地/联网处理、排队、转换中、成功、失败及输出文件。失败不阻止其他文件继续。
- 同名输出生成新名称，不覆盖原文件。
- 断网时本地能力可用；联网任务保留输入和错误说明，不显示虚假的成功状态。

## 上传与服务端

上传前显示所选文件、用途及服务器处理说明，并提供“同意并上传”和“取消”。默认不自动上传；用户拒绝后保留本地输入、编辑内容和可用的本地功能。

先使用受控的测试服务完成联调，公开上线需要真实 HTTPS 地址。App 未连接可用服务时，只展示真实可用的本地功能，并明确联网功能尚未连接。

服务按任务隔离临时目录，校验实际文件类型、文件大小和输出格式；提供任务状态及结果下载，使用不易猜测的任务凭证，不允许跨任务读取文件。转换进程设置时间和资源上限。结果下载完成并确认后删除服务端临时文件；未取回和失败任务按明确的保留期限清理，客户端展示实际策略。生产服务器地址、存储与清理策略在上线前确定，不预先声称已部署或“立即删除”。

服务端的 Word / PDF 渲染改用可部署的引擎，例如 LibreOffice；不能依赖用户电脑上的 Word COM。桌面版仍然保留，手机端在独立目录开发。

## 实施与交付阶段

1. 手机工程、本地文本编辑复制、文件/图片输入输出和基本本地转换；先完成可验证的核心闭环。
2. 转换服务、上传确认、任务和结果返回，接入复杂文档与公式识别。
3. 安卓安装包及真机测试；iOS 通过 macOS + Xcode 完成编译、签名和真机验证，之后准备测试分发及商店发布。

当前电脑是 Windows；已发现 Java、Docker，命令路径尚未发现 Flutter / Dart 或安卓 SDK。实施时需要准备工具链。iOS 的最终构建不能在当前 Windows 本机直接完成，需要本地或云端 macOS 环境以及相应签名配置。未完成 iOS 构建和真机验证前，不声称 iPhone 版已可安装。

本阶段目标先做可安装测试版本。商店账号、正式签名、服务器开通和发布由后续明确授权推进；目前没有收费、会员或广告需求。

## 验证标准

- 手机端拒绝上传时不发送文件；取消、失败和重试不丢失用户编辑。
- 编辑后的文本与复制和 TXT 保存内容逐字一致。
- 两端验证文件选择、相册输入、分享、中文文件名和长文编辑。
- 本地表格验证中文、长编号、前导零、日期时间、多工作表和公式值的边界。
- 图片验证设备支持的 HEIC 读写、方向、透明背景、尺寸与元数据选项。
- 文档与公式结果提供核对入口，不承诺复杂版式或识别完全准确。
- 安卓构建与 iOS 构建、真机验证分别记录；不能用网页预览通过代替手机构建通过。
